# Chat Archive

`chat-archive.html` —— 单文件 JSON 聊天记录档案室。双击用浏览器打开就能用，不需要服务器、不联网、无依赖。

第三版：档案袋首页 + 头像 + 全字段还原 + 双排版 + CSS 注入，冷调黑白灰。

## 能力

- **档案室首页**：每个角色一个档案袋卡片（纸舌 + 编号 + 花体水印字母），显示条数、时间跨度、最后一句预览。点开进入该角色的完整历史。
- **头像**：每个角色（包括 `user`）都能上传图片，自动裁成 160×160 存进 IndexedDB，换数据也不会丢。可把任一角色标记为「我方」，对话体里靠右显示。
- **两种排版**：`平铺`（文档式，群聊几十人也不乱）和 `对话体`（气泡，我方靠右）。随时切换。
- **全字段还原**：JSON 里的字段**全部自动保留，不用挑**。除映射掉的消息 / 发送者 / 时间三项外，其余字段直接以标签形式显示在每条消息下方；点消息右上角展开右侧详情面板，列出全部字段（含 `meta.client` 这类嵌套路径）和完整原始 JSON。顶部 `全部字段 / 精简 / 隐藏` 三档随时切换显示密度（字段多于 10 个时默认「精简」，显示前几个 + 「+N 个字段」，点它直接展开详情）。
- **搜索**：关键词全文搜索，中英文都走子串匹配，结果高亮。「仅匹配」只列命中条目，「全部+定位」保留上下文并在命中项间跳转（Enter / Shift+Enter）。
- **自定义 CSS**：面板里写样式实时生效并保存，附完整类名清单；导出的 HTML 用同一套类名，样式一起带走。
- **导入**：`.json` / `.jsonl` / `.ndjson`，拖拽或选择；也支持粘贴。自动识别字段，支持 `msg.content` 这类嵌套路径。
- **导出**：HTML（自带懒加载 + 搜索 + 头像 + 你的 CSS）、Markdown、JSON、纯文本。
- **本地缓存**：IndexedDB 自动保存，重开自动恢复档案、头像、我方、排版、字段密度和自定义 CSS。
- **手机可用**：顶栏在窄屏拆成两行，次要动作收进「⋯」下拉；角色栏和详情面板变成抽屉，点遮罩关闭。

## 实测（Chromium / headless）

| 规模 | 导入全流程 | 搜索 | IndexedDB 恢复 | 常驻 DOM |
|---|---|---|---|---|
| 20 万条 / 21 MB | 1.2 s | 25–144 ms | 0.4 s | 35 |
| 5 万条 × 20 字段（保留全部字段） | 1.2 s | 60 ms | — | 30 |
| 100 万条 / 102 MB | 5.1 s | 19–56 ms | 1.0 s | 24 |

100 万条时 JS 堆约 133 MB；5 万条 × 20 字段约 65 MB。

字段密度对滚动的影响（每帧 110px 连滚 60 帧，p50/p90）：`隐藏` 23/29 ms、`精简` 22/24 ms、`全部字段`（每条 25 个标签）23/31 ms —— 三者没有实质差别。

## 自定义 CSS 类名

写在「自定义 CSS」面板里即可，主程序和导出的 HTML 通用。

### 消息
| 类名 | 指向 |
|---|---|
| `.msg` | 一条消息的外层容器（两种排版都有） |
| `.msg.chat` | 对话体排版下的消息 |
| `.msg.self` | 被设为「我方」的消息，对话体里靠右 |
| `.msg.hit` | 搜索命中的消息 |
| `.bubble` | 对话体的气泡（平铺模式没有） |
| `.msg-name` / `.msg-time` / `.msg-idx` | 发送者名 / 时间 / 原始序号 |
| `.msg-text` | 消息正文 |
| `.msg-text.clamped` | 被折叠的超长正文 |
| `.msg-tags` / `.tag` | 字段标签行 / 单个标签 |
| `.tag k` / `.tag v` | 标签的字段名 / 字段值 |
| `.tag.more` | 「+N 个字段」那颗虚线标签 |
| `.avatar` / `.avatar img` | 头像圆片 / 上传的头像图 |
| `mark` | 搜索关键词高亮 |
| `.row` | 虚拟列表行容器 —— **别改 `position` 和 `transform`**，会打乱滚动 |

### 档案室与外壳
| 类名 | 指向 |
|---|---|
| `.folder` | 档案袋卡片 |
| `.folder::before` | 卡片顶上的纸舌 |
| `.folder-wm` | 右下角花体水印字母 |
| `.folder-name` / `.folder-latin` | 名字 / 花体副标题 |
| `.folder-stats` / `.folder-preview` | 统计 / 预览文字 |
| `.role` / `.role.active` | 左栏角色条目 / 选中态 |
| `.topbar` / `.mainbar` / `.sidebar` / `.viewport` | 顶栏 / 标题栏 / 左栏 / 滚动区 |
| `.top-actions` / `.lbl` | 顶栏动作组（手机上是下拉菜单）/ 菜单里的文字标签 |
| `.scrim` | 手机上抽屉后面的遮罩 |
| `.detail` / `.frow` / `.fkey` / `.fval` | 详情面板 / 字段行 / 字段名 / 字段值 |
| `.script` | 所有花体装饰文字 |
| `.datechip` | 滚动时浮现的日期胶囊 |

### 主题变量
写在 `:root{}` 里覆盖：
`--bg` `--panel` `--panel-2` `--sunk` `--fg` `--fg-2` `--fg-3` `--fg-4` `--line` `--line-2` `--ink` `--paper` `--mark-bg` `--script` `--mono`

```css
/* 例：把对方气泡改成描边风格 */
.msg.chat .bubble { background: transparent; border-color: var(--fg-3); border-radius: 0; }
/* 例：名字用花体 */
.msg-name { font-family: var(--script); font-style: italic; font-size: 16px; }
/* 例：整体偏暖一点 */
:root { --bg: #f7f6f4; --line: #e7e3dd; }
```

## 架构

```
文件 ──► Worker: JSON.parse ──► 字段探测 ──► 映射确认（含附加字段 / 保留原始记录）
                                              │
                          ┌───────────────────┴────────────────────┐
                          ▼                                        ▼
              列式数据（主线程）                        搜索索引（Worker 内）
        texts / times / senderIdx / inline / rawJson       分块大字符串 + 偏移表
                          │                                        │
                          ▼                                        ▼
              Fenwick 树 + 变高虚拟列表  ◄── view: Int32Array ──  indexOf 扫描
```

### 关键取舍

**搜索不建倒排索引。** 几十万条中文做倒排要 bigram 分词，索引体积超过原文本身，构建还要数秒。改成 Worker 里把消息按块拼成大写字符串（每块 ≤ 2 万条 / 800 万字符）配 `Int32Array` 偏移表，用原生 `indexOf` 扫，命中后二分定位再跳下一条。中英文同一套逻辑，零构建成本。块内消息用 U+0001 分隔，避免跨条误匹配。

**虚拟列表按实测高度走 Fenwick 树。** 消息长度差异极大，固定行高滚动条会乱跳。先按「字符数 ÷ 每行可容字符数」估高（每行字符数由采样的中西文比例推算，两种排版各算各的），渲染后实测真高回写 Fenwick 树，并用锚点补偿滚动位置。前缀和与二分定位都是 O(log n)。

**超长列表压缩滚动空间。** 浏览器对单个元素高度有上限（Chrome 约 3.3e7 px，Firefox 约 1.8e7 px）。100 万条虚拟总高约 5870 万 px，直接设会被截断，后 43% 永远滚不到。总高超过 1500 万 px 时压缩滚动空间，用 `scale` 在滚动坐标和虚拟坐标间换算 —— 实测 100 万条任意位置定位误差 ≤ 1 行。

**字段不做取舍，只在渲染时按需解析。** 保留每条的原始 JSON 才能做到「一个字段不丢」，代价是内存约等于原文件的两倍，所以导入时按数据大小自动决定默认开关（超过 6000 万字符默认关闭），界面上标出预计占用。展示侧不预先摊平成列，而是渲染到哪条才 `JSON.parse` 哪条，配一个 4000 条上限的缓存 —— 可见的永远只有二三十条，所以「每条 25 个字段全展开」和「完全不显示字段」的滚动开销实测一样。

**移动端顶栏拆行而不是塞下。** 原来一行要放品牌、搜索、排版切换和五个图标，390px 宽根本排不下，会把文档撑到 596px，浏览器只好整体缩放 —— 页面就全糊了。现在窄屏下搜索独占第二行，次要动作收进「⋯」下拉，实测各个路由都严格等于屏宽。抽屉改用 `#reader` 作定位参照（之前没有定位祖先，`inset:0` 一路顶到屏幕顶部把顶栏盖住了）。

### 其他

- Worker 用 Blob URL 创建；若被 `file://` 策略拦截，自动回退到主线程跑同一份代码。
- 花体字优先用 Cormorant Garamond（在线时加载），离线自动退到 Didot / Bodoni / Georgia，不影响排版。
- 所有文本转义后再插入，`<script>`、`<img onerror>` 之类只按字面显示；高亮不破坏转义。
- 图标全是内联 SVG，没有 emoji。跟随系统深色模式，也可手动切换。
